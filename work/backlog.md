## Worker services (`docs/worker-crates.md`, `crates/worker-host`)

- **P2**: The worker gRPC client (`crates/worker-host/src/client.rs`) sets no deadline on unary RPCs. `connect` succeeds as soon as TCP connects, so against a wedged worker (or a non-gRPC listener) the first RPC blocks forever. The agent's job runner bounds its own calls with `tokio::time::timeout` (ADR-235), but every other client of `worker-host` does not. Add a deadline layer in `worker-host` keyed by RPC path (unary calls bounded, `SubscribeEvent` unbounded) and drop the runner's own timeouts. Done when: a unary call against a listener that never answers fails within the configured deadline, and a `SubscribeEvent` stream stays open past it.
