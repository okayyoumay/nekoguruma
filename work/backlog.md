## Status

**Current milestone (decided by the maintainer, 2026-10-14):** M2, the diagnostic runtime: vehicle knowledge supplied as data (CSV tables + Starlark) is turned into IR and executed by the agent against `sim-ecu` through both worker kinds, with IR golden tests, a fuzz target for malformed IR, and a procedure interrupted mid-run resuming at the IR level (design 8.1, 8.2, 8.4, 12.1). M1, the local end-to-end path with the interrupted-write resume, is finished.

Where the crates stand:

- `shared-proto`: type definitions for job specs, states, failure codes, capabilities
- `diag-ir`: instruction set, section attributes (interruptibility, idempotency), the VM with its serialized state, the `DiagHost` trait, and the restart declaration (identity, preconditions, flash recovery plans; ADR-245)
- `sim-vci`: J2534 exported functions and `PASSTHRU_MSG`, switching of `unsigned long` width, fault injection by control command (ADR-238); the ECU state can be kept in a file across worker processes (ADR-241)
- `sim-ecu`: UDS services for M1 (session, reset, security access, DIDs, DTCs, routines, download) with flash state, resume and fault injection aimed at a service or a request prefix; `sim-vci` delegates ISO 15765 traffic to it
- `j2534-defs`: J2534 constants, protocol name resolution, COMPARAM -> SET_CONFIG mapping (tested)
- `ngr-library-resolver`: shared library resolution for J2534 v04.04 and the D-PDU API, with both 7.2 pre-load checks (writability, signer); both worker services and the agent's ABI detection resolve through it, and it is the only J2534 lookup
- `ngr-hw-checks`: harness of the optional real-hardware checks (design 13.5, ADR-275): the hardware profile and its parser, the check declarations and their listing, and the module match; no check reaches a VCI yet (P1 items under "CI and repository")
- Worker crates (`iso22900*`, `j2534-0404*`, `vci-service-*`): imported working services (`docs/worker-crates.md`)
- `agent`: job runner (ADR-235) on a j2534-0404 worker link, the write-job journal (ADR-244, ADR-252), job guards (per-VCI and per-vehicle locks, reprogramming slot), and the restart of an interrupted write from the journal (design 5.6, 8.2.5), tested end to end for an agent killed, a worker crashed, an ECU power loss or a VCI disconnect mid-transfer (also with the VCI still unplugged at the next run), kills after RequestTransferExit, the ECUReset teardown paths, the completed path and the read-back verification, on Linux and Windows (`crates/j2534-0404-service/tests/agent_restart_end_to_end.rs`); the `ngr-agent` binary has one command, `run` (`crates/agent/docs/ngr-agent.md`)

## Development process (`work/`, `.claude/`, `CLAUDE.md`, `.github/` review rules)

- **P1**: Auto-merge for low-risk `backlog-loop` pull requests. The loop records `scripts/classify-pr-risk.sh`'s verdict on every loop PR (shadow mode) while the maintainer still merges everything. Before any PR merges without the maintainer: compare the recorded verdicts with the maintainer's own judgement; add a CI check that fails on long passages matching the standards in `vehicle-comm-specs` (copyright); require a clean automated review (Codex, or Copilot where the PR fell back to it) plus a fresh `edge-case-hunter` pass; merge through GitHub auto-merge (required checks, no admin bypass); run the classifier from a worktree of `origin/main` after fetching it, so a PR cannot change the rules it is judged by; add a stop switch and a log of auto-merged PRs that records each PR's check runs and reviews as GitHub reports them, not the description's checkboxes (those can be stale); change CLAUDE.md ("Pull requests" step 5) and the review guidelines in `.github/`, and write an ADR. Done when: low-risk loop PRs merge without the maintainer and the ADR records the rules. Blocked on: loop PRs that the classifier rates LOW, and the maintainer's comparison of those verdicts with their own judgement. The first eleven loop PRs (#80 to #92) were all rated HIGH, since each changed agent code, an ADR or the design document, and the maintainer found no verdict wrong, so auto-merge stays off until LOW verdicts exist to compare.

- **P1**: `pr-review-loop` has no sweep for the kinds of finding that recur within one PR. Its fix step fixes the spot a finding names, so the same kind of gap elsewhere in the diff is found only in later rounds (cross-document drift between an ADR, `INDEX.md`, the design document and the glossary; qualifiers dropped in a paraphrase; a rule applied to one case but not its siblings; what a journaled marker binds to at a restart; safety invariants; citations without edition and clause). Done when: `pr-review-loop` checks the whole diff for those kinds before the first review request and after each fix round, and a fix for one finding also fixes the same kind elsewhere in the same push.
- **P1**: A loop PR that passes every PR check can still fail on `main`, where `agent-release` and the full Windows test run only, and each such failure needs a fix PR outside the loop. Two gaps let this through: CLAUDE.md's trigger for running the release-build agent tests locally is a change to `cfg(not(debug_assertions))` code, which misses a test-only change whose outcome depends on the build's policy; and nothing says what to run locally for a change to an end-to-end test that pull requests skip or run differently on Windows. Done when: that trigger also covers tests whose outcome depends on the build's policy, and `pr-review-loop` says what to run locally when a PR touches tests that pull requests skip on Windows.
