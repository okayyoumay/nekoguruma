## Status

**Current milestone (decided by the maintainer, 2026-10-14):** M2, the diagnostic runtime: vehicle knowledge supplied as data (CSV tables + Starlark) is turned into IR and executed by the agent against `sim-ecu` through both worker kinds, with IR golden tests, a fuzz target for malformed IR, and a procedure interrupted mid-run resuming at the IR level (design 8.1, 8.2, 8.4, 12.1). M1, the local end-to-end path with the interrupted-write resume, is finished.

Where the crates stand:

- `shared-proto`: type definitions for job specs, states, failure codes, capabilities
- `diag-ir`: instruction set, section attributes (interruptibility, idempotency), the VM with its serialized state, the `DiagHost` trait, and the restart declaration (identity, preconditions, flash recovery plans; ADR-245)
- `sim-vci`: J2534 exported functions and `PASSTHRU_MSG`, switching of `unsigned long` width, fault injection by control command (ADR-238); the ECU state can be kept in a file across worker processes (ADR-241)
- `sim-ecu`: UDS services for M1 (session, reset, security access, DIDs, DTCs, routines, download) with flash state, resume and fault injection aimed at a service or a request prefix; `sim-vci` delegates ISO 15765 traffic to it
- `j2534-defs`: J2534 constants, protocol name resolution, COMPARAM -> SET_CONFIG mapping (tested)
- `ngr-library-resolver`: shared library resolution for J2534 v04.04 and the D-PDU API, with both 7.2 pre-load checks (writability, signer); both worker services and the agent's ABI detection resolve through it, and it is the only J2534 lookup
- Worker crates (`iso22900*`, `j2534-0404*`, `vci-service-*`): imported working services (`docs/worker-crates.md`)
- `agent`: job runner (ADR-235) on a j2534-0404 worker link, the write-job journal (ADR-244, ADR-252), job guards (per-VCI and per-vehicle locks, reprogramming slot), and the restart of an interrupted write from the journal (design 5.6, 8.2.5), tested end to end for an agent killed, a worker crashed, an ECU power loss or a VCI disconnect mid-transfer (also with the VCI still unplugged at the next run), kills after RequestTransferExit, the ECUReset teardown paths, the completed path and the read-back verification, on Linux and Windows (`crates/j2534-0404-service/tests/agent_restart_end_to_end.rs`); the `ngr-agent` binary has one command, `run` (`crates/agent/docs/ngr-agent.md`)
- `shared-crypto`, `vendor-manifest`, `server`: placeholders only. `diag-frontend` reads a CSV definition directory into typed rows (`tables`); the rest of the CSV-to-IR conversion and the Starlark lowering are not written (the procedure language is designed: Starlark, ADR-254)

- **P1**: Auto-merge for low-risk `backlog-loop` pull requests. The loop records `scripts/classify-pr-risk.sh`'s verdict on every loop PR (shadow mode) while the maintainer still merges everything.
